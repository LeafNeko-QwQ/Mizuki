# MDX 语法指南

MDX 让你继续写熟悉的 Markdown，同时在普通 Markdown 表达不了的地方加入组件和 JavaScript 表达式。本文介绍在内容驱动的 Astro 站点里写文章时最有用的那些语法。

:::note[什么是 MDX？]
`.mdx` 文件仍然是 Markdown 文档。标题、列表、链接、图片、代码块等 Markdown 语法照常可用；而导入、组件、JSX 和表达式则作为可选的扩展能力出现。
:::

## Frontmatter

每篇文章都以 YAML frontmatter 开头。它定义文章页、列表、搜索结果和订阅源会用到的元数据：

```yaml
---
title: My MDX Article
published: 2026-08-08
description: A short introduction shown in article previews.
tags: [Markdown, MDX]
category: Guides
draft: false
---
```

frontmatter 只放元数据。导入语句和 JavaScript 声明应写在结束的 `---` 之后。

## 标准 Markdown

MDX 文章的大部分内容仍应是普通 Markdown。这样源码好读，RSS 和 Atom 读者也能拿到一份可用的静态版本。

```markdown
## A section heading

- A list item
- **Bold text** and *emphasis*
- [A normal link](https://example.com/)

> A blockquote remains a blockquote.
```

## 导入和使用组件

MDX 可以在顶层导入 Astro 组件，并直接在文档里使用。组件名必须以大写字母开头。

```mdx
import Notice from "../../components/Notice.astro";

export const message = "Props can come from an MDX expression.";

<Notice label={message} />
```

下面这块面板就是本文实际渲染出来的组件：

<ContentPipelineFixture label={componentMessage} />

可复用的界面元素或结构化内容用组件；普通叙述尽量用 Markdown，文章才便于迁移和阅读。

## JavaScript 表达式

顶层的 `export const` 声明可以为文档准备变量。用花括号插入 JavaScript 表达式：

```mdx
export const topics = ["组件", "表达式", "扩展 Markdown"];

This guide covers {topics.length} topics: {topics.join(", ")}.
```

这里的实时表达式会算出 {topics.length} 个主题：{topics.join("、")}。

表达式在构建期间必须是确定性的。`window`、`document` 这类只在浏览器里存在的 API，应放在组件脚本里，而不是 MDX 模块顶层。

## 提示块

提示块可以突出信息，不需要自定义组件：

:::tip[能用简单写法就用简单写法]
普通叙述用 Markdown，小的动态值用 MDX 表达式，需要复用标记或行为时才上组件。
:::

````markdown
:::tip[Optional title]
This content is emphasized as a tip.
:::
````

## Wiki 链接

行内的 Wiki 链接指向另一篇文章，同时让句子保持通顺。例如接下来可以看 [[guide|内容编写指南]]。

单独占一行的 Wiki 链接会变成一张带元数据和封面的文章卡片：

[[guide]]

```markdown
Read [[guide|the content guide]] for more details.

[[guide]]
```

## 数学与化学

行内公式用一对美元符号，独立公式用两对。`mhchem` 扩展还能写化学式。

爱因斯坦的质能关系是 $E = mc^2$。

$$
\int_{-\infty}^{\infty} e^{-x^2}\,dx = \sqrt{\pi}
$$

一个化学反应可以写成 $\ce{H2O + CO2 -> H2CO3}$。

```markdown
Inline: $E = mc^2$

Display: $$\int_0^1 x^2\,dx = \frac{1}{3}$$

Chemistry: $\ce{H2O + CO2 -> H2CO3}$
```


## 图片与图注

图片的 alt 文本是给辅助技术用的描述。Markdown 的 title 会变成可见图注，另外可用 `w-N%` 控制宽度。

![一张方形演示图 w-60%](/images/demos/image-grid-demo/square-1.webp "由 Markdown 图片 title 生成的图注")

```markdown
![Descriptive alt text w-60%](./image.webp "Visible image caption")
```

可用宽度范围是 `w-1%` 到 `w-100%`。想让图片走正常的响应式宽度，就不要写这个标记。

## 站内链接与站外链接

相对链接，以及使用配置的站点域名开头的绝对地址，会被判定为站内链接。指向其它域名的链接会带上主题配置的外链属性。

- 访问[关于页（使用站点相对地址）](/about/)。
- 和[一个外部参考](https://example.com/reference)对比一下。

站内内容用相对路径。像 https://example.com/ 这样的外部域名，主题会单独识别。

## 写可迁移的 MDX

文章页、RSS 和 Atom 共用同一套内容处理流程。交互脚本会从订阅源里移除，但组件、提示块、Wiki 链接、数学公式、代码组和图片产生的语义化 HTML 仍然可读。

为了输出稳定：

1. 主要说明留在 Markdown 里。
2. 图片给有意义的 alt 文本，组件产出语义化 HTML。
3. 顶层表达式里不要用浏览器全局对象。
4. 保证在客户端 JavaScript 执行之前，有用信息就已经可见。
5. 发布前跑一遍 `pnpm test`、`pnpm check` 和 `pnpm build`。

MDX 最好当作 Markdown 的扩展，而不是替代品。先写朴素的内容，只在能讲得更清楚或更能复用时，才引入表达式和组件。
